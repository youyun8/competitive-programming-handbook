core_knowledge:
  - 先進先出淘汰策略
  - 佇列維護順序、布林表維護成員資格
judgment: 需求同時包含「是否存在」與「最早加入者」；只用佇列查存在較慢，只用集合又無法得知淘汰順序，兩者搭配最清楚。
hints:
  - 每個單字只分成「目前已在記憶體」與「不在」兩種情況；命中時不改變原有順序。
  - 用佇列保存仍在記憶體中的加入順序，再用布林陣列回答是否命中。
  - 未命中時答案加一；若佇列已有 M 個元素，先將隊首的布林標記清除並出隊，再把新單字標記並入隊。
solution_outline: 依序掃描單字。布林表命中便略過；未命中時計數，必要時從 FIFO 佇列淘汰隊首並清除標記，最後加入新單字。
proof_or_invariant: 每次處理後，佇列由前至後恰為目前記憶體內單字的存入先後順序，布林表也恰標記這些單字。未命中時若容量已滿，隊首正是規則要求淘汰者；因此每一步與題目系統一致，累計次數即為答案。

  - 命中時仍把單字移到隊尾，誤做成 LRU 而非 FIFO

  - 在加入新單字後才判斷容量，造成短暫越界或淘汰錯誤

cpp_solution: |
  #include <bits/stdc++.h>
  using namespace std;

  int main() {
      ios::sync_with_stdio(false);
      cin.tie(nullptr);
      int capacity, word_count;
      if (!(cin >> capacity >> word_count)) return 0;
      queue<int> memory_order;
      vector<bool> in_memory(1001, false);
      int lookups = 0;
      for (int i = 0; i < word_count; ++i) {
          int word;
          cin >> word;
          if (in_memory[word]) continue;
          ++lookups;
          if (static_cast<int>(memory_order.size()) == capacity) {
              in_memory[memory_order.front()] = false;
              memory_order.pop();
          }
          memory_order.push(word);
          in_memory[word] = true;
      }
      cout << lookups << '\n';
      return 0;
  }
